1. Use Case Summary

Goal: Rebuild the public CHN Bariatric & Medical Weight Loss marketing page as a fast static site and a working deployment-pipeline test for Astro on Cloudflare — with two live AI features: an "Information at a glance" Q&A panel wired to an internal Databricks Genie space, and a site-wide floating chat bot that mirrors the Yext Chat pop-up on the live ecommunity.com.

Business value: Content pages cost nothing to serve — static assets on Cloudflare's CDN with no origin round-trip. The two AI features are isolated and independent: Genie's answers require an Azure credential, so that feature gets a single edge function that keeps the secret server-side; the Yext bot uses a published public key, so it runs entirely in the browser and adds zero server surface. Adding, changing, or removing either feature touches one component.

Key property: Three runtime concerns — static content, the Genie edge function, and the Yext bot — share one Astro project but are decoupled at runtime. The CDN serves HTML with no code execution; the Worker runs only for /api/genie; the Yext widget talks straight to Yext's CDN. A failure in any one does not affect the others.

2. What the System Does

  • Rebuilds the CHN Bariatrics landing page in Astro — header, hero, assessment CTA, services, FAQ, support, locations, providers — as components under src/.
  • Prerenders every route to static HTML/CSS at build time; images are hot-linked from ecommunity.com.
  • Ships the collapsible "Information at a glance" panel (InfoAtAGlance.astro) with suggestion chips and a free-text box.
  • Exposes one server route, /api/genie, running as a Cloudflare Worker: authenticates a Microsoft Entra service principal (client-credentials), caches the bearer token per isolate, starts/continues a Databricks Genie conversation, polls to COMPLETED, and returns { answer, conversationId }. A GET on the same route is a value-free readiness check.
  • Ships a site-wide floating Yext chat bot (YextChat.astro), rendered once in Base.astro so it appears on every page.
  • The Yext widget calls the Yext Chat API directly from the browser with a public client key, keeps its transcript in sessionStorage, and renders replies through the shared miniMarkdown helper.

3. Project Context

The project lives in the bariatrics/ subdirectory of the IndyCrew/cloudflare repo; all commands run from there. Astro's Cloudflare adapter emits a static client bundle plus a Worker entry point. Non-secret Databricks IDs are committed in wrangler.jsonc vars; only DATABRICKS_CLIENT_SECRET is set as a secret. There is no database and no server the site owns — Genie is reached only through the one function, and Yext is reached only from the client.

7. Yext Chat Bot Detail

  • Config (component frontmatter): apiDomain https://cdn.yextapis.com, botId chatbotv2, public apiKey, API version 20230101, title "eCommunity AI Chat Bot", greeting, and 8 suggestion chips (Get Care Now, Appointments, Costs & Billing, MyChart, Find a Doctor, Careers, Mammography, Screenings).
  • UI: fixed launcher bottom-right → 380×560 panel; header carries restart and close; goes full-screen under 480px.
  • Request: POST {apiDomain}/v2/accounts/me/chat/{botId}/message?v={version}&api_key={apiKey} with the entire messages array plus conversationId each turn.
  • Response: data.response.message (appended as a BOT turn), data.response.conversationId (persisted). Errors read from data.meta.errors[0].message.
  • Persistence: transcript + conversationId saved to sessionStorage["ychat:"+botId], restored on load, so the conversation survives page navigation within the tab. Restart clears it.
  • Resilience: on a failed turn the widget removes the unanswered user message from history and shows an inline error bubble.
Why no server: the Yext chat key is a public client credential — the live ecommunity.com ships it in page source too. Proxying it through a Worker would add latency and a failure point without hiding anything, so the widget calls Yext directly.

8. Genie Edge Function Detail

Route: /api/genie  ·  POST body: { question, conversationId? }  ·  Runs as: a Cloudflare Worker (rest of the site prerendered).

  • OPTIONS — CORS preflight (* origin, POST only).
  • GET — readiness check that returns booleans only: whether DATABRICKS_CLIENT_SECRET and each non-secret ID are present, plus any near-miss secret key name reported by length only. Never returns names or values.
  • POST validate — reject empty questions and anything over 1000 characters (400).
  • getToken() — client-credentials grant against Entra; token cached per isolate until 60s before expiry.
  • genieFetch() — wrapper over /api/2.0/genie…; non-2xx becomes a 502 with a truncated detail.
  • Start vs. continue — no conversationId → start-conversation with conversation_type = mode; otherwise POST a message to the existing conversation.
  • pollMessage() — poll until COMPLETED; fail fast on FAILED/CANCELLED; 504 after ~55s (backoff 0.8s → 3s).
  • answerFromMessage() — prefer attachment text, then query descriptions, then msg.content.
Statefulness note: the token cache is per-isolate and non-durable — it only avoids re-auth during bursts on a warm isolate. Genie conversation continuity is the client's job.

12. Summary

"CHN Bariatrics is an Astro rebuild of a single Community Health Network marketing page, prerendered to static HTML on Cloudflare's edge. It carries two AI chat features that are deliberately built differently. 'Information at a glance' needs an Azure credential to reach an internal Databricks Genie space, so it gets one Worker route — /api/genie — that holds the secret, authenticates a service principal, polls Genie for an answer, and returns only the text. The floating 'eCommunity AI Chat Bot' uses Yext's public client key, the same one the live site ships, so it runs entirely in the browser against Yext's CDN with no server of ours in the path."

"The architectural value is that the trust model follows the credential. A secret gets a server boundary; a public key does not. Static content, the Genie function, and the Yext widget are each independently swappable, and an outage in any one leaves the other two untouched."
